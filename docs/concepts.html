in layers.

Layerdots composes a public personal repository with private work overrides, then treats your home directory as the place where new changes begin.

The central promise
  1. Public content stays public.
  2. Private content stays in its overlay.
  3. Your home sees one coherent result.
  4. You decide where each new change belongs.
01 / Model

One result, assembled from separate authorities.

A base contains ordinary files. An overlay contains additions, full replacements, patches, and deletions. Composition produces the effective files used in your home directory.

02 / Places

Five locations, five distinct jobs.

Most confusion disappears once Git remotes, local clones, staging, derived state, and live home files are treated as separate places.

Remote Git repositories

Shared history

Public GitHub holds the base. GitHub Enterprise holds the private overlay. These are the cross-machine source of truth.

github.com/you/dotfiles git.work.example/you/work-dotfiles
Tool-managed clones

Local Git work

Layerdots fetches, generates patches, and creates coordinated commits here. Users normally edit the target, not these clones.

$XDG_DATA_HOME/layerdots/repos/...
Staged transaction

Proposed next state

A reviewable plan for assignments, rebases, target writes, and conflict resolutions. It is not yet committed or pushed.

$XDG_STATE_HOME/layerdots/transactions/...
Derived state

Merge memory

The last applied composition, temporary compositions, and rollback journals make safe three-way updates possible.

$XDG_STATE_HOME/layerdots/targets/...
Target home

Live configuration

The files programs actually read. Direct edits here become unassigned changes until routed to a layer.

~/.gitconfig ~/.config/nvim/init.lua
Staging is not a third source of truth. It is a disposable, reviewable proposal between current state and the next committed/applied state.

07 / Rules

The boundaries that keep composition safe.

Layerdots is intentionally narrower than a general configuration generator.

01

Explicit paths only

Unmanaged files and sibling paths are never changed by composition or apply.

02

No private descent

Overlay content enters a public lower layer only through an explicit assignment.

03

Review before durability

Assignments, rebases, and target transitions enter a staged transaction before commit, push, or apply.

04

Journal every apply

Multi-file target writes roll back if any operation fails halfway through.

05

Git remains Git

System Git supplies authentication, hooks, signing, patching, merges, and remote transport.

06

One stack per target

Competing stacks cannot claim the same home directory and recreate ambiguous ownership.

Build the composition engine first.

The first vertical slice proves composition, provenance, whole-hunk assignment, and three-way overlay rebasing before remote lifecycle or TUI work begins.
